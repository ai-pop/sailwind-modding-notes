# 88. Исключение якорей из общей физики предметов: почему якорь нельзя бросать как обычный груз

Технический анализ отзывов пользователей на моды физики предметов (запрос на SailwindItemPhysics: *"it doesnt affect the anchor, that would be nice to throw around"*). Заметка объясняет, чем архитектура якоря (`Anchor : PickupableItem`) принципиально отличается от обычных предметов с twin-моделью (`ShipItem` / `ItemRigidbody`), и почему попытка применить к якорю общие физические патчи приводит к поломке швартовки и физики корабля.

Связано с [29](29-anchor-mooring-ropes.md), [44](44-itemrigidbody-field-map-contract.md) и [85](85-anchor-joint-physics-seabed-setting-and-stowed-mass-reduction.md).

---

## 1. Архитектурное отличие якоря от обычного предмета

В коде Sailwind v0.38 (`Assembly-CSharp.dll`) якорь не является обычным переносимым предметом:

| Характеристика | Обычный груз (`ShipItem`) | Якорь (`Anchor : PickupableItem`) |
|---|---|---|
| **Физическая модель** | Twin-модель: Visual GO (`kinematic`) + Twin GO (`ItemRigidbody`, dynamic) | **Одиночное тело:** `Anchor` сам является динамическим `Rigidbody` без отдельного visual/twin разделения |
| **Связь с кораблем** | Свободное тело, удерживается в зоне палубы через `BoatLocalItems` | **Жесткая связь:** постоянно привязан к лодке через `ConfigurableJoint` (`joint.connectedBody`) |
| **Плавучесть** | Расчитывается через `SimpleFloatingObject` (Crest) | **Тонет всегда:** не имеет компонента плавучести |
| **Масса в походном состоянии** | Постоянна (`61-item-catalog-mass-table-units.md`) | **Динамически меняется:** падает до **0.2 кг** при подъеме на нос (`limit < 1f`, [заметка 85](85-anchor-joint-physics-seabed-setting-and-stowed-mass-reduction.md)) |

---

## 2. Почему общие патчи физики ломают якорь

Если мод на физику предметов попытается обработать `Anchor` по тем же правилам, что и ящики или бочки, произойдет конфликт сразу в трех подсистемах:

```
[ Мод пытается применить ThrowImpulse / Twin Override к Якорю ]
                        │
                        ├──────────────────────────────────────┐
                        ▼                                      ▼
           [ Конфликт с ConfigurableJoint ]        [ Конфликт с массой 0.2 кг ]
           Импульс броска превышает                В момент броска масса = 0.2 кг,
           joint.linearLimit (длину троса)         импульс запускает якорь в космос,
                        │                          а затем трос дергает нос корабля
                        ▼
            [ ПОЛОМКА ШВАРТОВКИ И КРУШЕНИЕ СУДНА ]
            Лебедка блокируется, якорь не цепляется за дно
```

### 2.1. Конфликт с ограничением длины троса (`joint.linearLimit`)
Якорный канат ограничивает максимальное удаление якоря от корабля (`joint.linearLimit.limit`). Если при броске якоря мод применит к нему скорость в течение 12 кадров (`ThrowImpulse.Plant`, [заметка 57](57-vanilla-drop-throw-mechanics.md)), якорь долетит до предела каната, после чего `ConfigurableJoint` рывком остановит тело. Этот рывок создаст гигантский обратный импульс на `connectedBody` — нос лодки резко уйдет под воду.

### 2.2. Конфликт с динамической массой (`0.2 кг`)
В походном положении на носу лодки якорь весит всего **0.2 кг** ([заметка 85](85-anchor-joint-physics-seabed-setting-and-stowed-mass-reduction.md)). Если мод рассчитает силу броска или инерцию на основе текущего `rb.mass = 0.2f`, якорь улетит с неестественно огромной скоростью.

### 2.3. Нарушение условий зацепления за грунт (`SetAnchor`)
Для зацепления за дно (`set = true`) якорь должен лежать на боку (`Angle > 60°`) и прекратить движение (`!audio.isPlaying`). Принудительное задание скорости от мода не позволит якорю успокоиться на грунте.

## 3. Практическое решение для поддержки броска якоря

Чтобы добавить возможность швырять якорь за борт без разрушения физики судна, мод должен реализовывать **специальный фильтр для `Anchor`**:

```csharp
public static void TryThrowAnchorSafe(Anchor anchor, Vector3 handVelocity)
{
    Rigidbody rb = anchor.GetComponent<Rigidbody>();
    ConfigurableJoint joint = anchor.GetComponent<ConfigurableJoint>();

    // 1. Проверяем, что якорь не зацеплен и канат вытравлен хотя бы на 2 метра
    if (anchor.IsSet() || joint.linearLimit.limit < 2f)
        return;

    // 2. Восстанавливаем настоящую массу перед броском (иначе 0.2 кг улетит)
    if (rb.mass < 10f)
        rb.mass = 100f; // Возвращаем базовую массу якоря

    // 3. Ограничиваем скорость броска так, чтобы якорь не дергал канат
    float maxSafeSpeed = Mathf.Min(8f, joint.linearLimit.limit * 0.8f);
    Vector3 launch = Vector3.ClampMagnitude(handVelocity * 1.2f, maxSafeSpeed);

    // 4. Применяем однократный импульс (ForceMode.Impulse), НЕ используя 12-кадровый ThrowImpulse
    rb.AddForce(launch, ForceMode.VelocityChange);
}
```

### 3.1. Правила безопасности для мододела
1. **Исключайте `Anchor` из общих систем Twin-физики:** проверяйте `item is Anchor` или наличие `ConfigurableJoint` при поиске twin-тел. Якорю не нужны `BoatZoneGhost`, `ShiftingRigidbody` или модовая плавучесть.
2. **Используйте `ForceMode.VelocityChange` единоразово:** никогда не перезаписывайте `rb.velocity` якоря в течение нескольких кадров, позвольте `ConfigurableJoint` свободно гасить скорость при натяжении каната.
3. **Проверяйте запас каната:** блокируйте бросок якоря, если вытравленная длина троса (`GetRopeLength()`) составляет менее 2 метров.
