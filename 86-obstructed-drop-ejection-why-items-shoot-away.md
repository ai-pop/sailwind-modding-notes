# 86. Бросок с перекрытием (красный контур): почему предметы «улетают» и как ваниль их перераскладывает

Технический разбор одной из самых частых проблем в модах на физику предметов (включая отзывы пользователей на SailwindItemPhysics): **почему при сбросе предмета с перекрытием (красный контур, клавиша `T`/`F`) он мгновенно отлетает с огромной скоростью («shoot away»)**, тогда как в ванильной игре предметы плавно перераскладываются и «втискиваются» в стопку.

Связано с [54](54-go-pointer-big-item-decollision.md), [59](59-velocity-zeroing-release-frame-pose.md), [60](60-held-readers-throw-key-binding.md) и [84](84-pickupable-item-collision-checker-and-decollision.md).

---

## 1. Как работает ванильное «втискивание» предметов в стопку

Когда игрок держит ящик и пытается положить его в тесное пространство между другими ящиками (или принудительно бросить через `T`/`F` при горящем красном контуре), в ванильной игре происходит следующий процесс:

```
[ Игрок нажимает Drop/Throw (T / F) при перекрытии ]
                        │
                        ▼
      [ PickupableItem.DropItem() ]
  item.held = null; visual.layer = 0 (Default)
                        │
                        ▼
   [ ItemRigidbody.FixedUpdate() (кадры 1..10) ]
   twinCollider остаётся isTrigger / kinematic в кадре релиза
   Physics.ComputePenetration → мягкое выталкивание без импульса
                        │
                        ▼
    [ Предмет плавно «втискивается» на полку/в стопку ]
```

### 1.1. Почему ванильные ящики не отлетают при пересечении
1. **Отсутствие твердого контакта в момент релиза:** В ванильном `ItemRigidbody` ([заметка 59](59-velocity-zeroing-release-frame-pose.md)) физический twin-коллайдер удерживаемого предмета имеет флаг `isTrigger = true` и/или является кинематическим (`isKinematic = true`) на протяжении удержания и в первый такт после освобождения.
2. **Нулевая начальная скорость:** В момент `DropItem()` ванильный код принудительно обнуляет линейную скорость (`rigidbody.velocity = Vector3.zero`).
3. **Плавная работа `ComputePenetration`:** Выталкивание из препятствия происходит за счет геометрического сдвига деколлизии (`decollisionVector`, [заметка 84](84-pickupable-item-collision-checker-and-decollision.md)), а не из-за контактного импульса твердых тел PhysX. Поэтому ящик просто плавно смещается в ближайшую свободную точку («re-shuffles itself»).

## 2. Почему в модах на физику возникает «катапультирование» (Shoot Away)

В модах на физику предметов (таких как SailwindItemPhysics v4.x/v5.x) реализуется динамическое удержание («physics in hands») или импульс броска (`MomentumThrow` / `ThrowImpulse`). При сбросе предмета с перекрытием это приводит к взрывному багу:

```
[ Мод: сброс предмета при перекрытии геометрии (красный контур) ]
                        │
                        ├──────────────────────────────┐
                        ▼                              ▼
          [ Twin-коллайдер — твердый ]       [ Применяется ThrowImpulse ]
          (col.isTrigger = false)           rb.velocity = handVelocity
                        │                              │
                        └──────────────┬───────────────┘
                                       ▼
                     [ PhysX: Penetration Depth Solver ]
                     Глубокое пересечение твердых тел
                     + принудительная скорость
                                       │
                                       ▼
            [ КАТАПУЛЬТИРОВАНИЕ ПРЕДМЕТА («SHOOT AWAY») ]
            Импульс выталкивания сотни ньютонов → ящик улетает за борт
```

### 2.1. Два источника взрывного импульса
| Источник | Техническая причина | Результат в PhysX |
|---|---|---|
| **Твердый Twin-коллайдер (`isTrigger = false`)** | Мод делает twin-коллайдер твердым, чтобы предмет стукался о стены в руках (`HoldSolidColliders`). Если сбросить предмет, когда он уже врезан на 5–10 см в другой ящик, PhysX мгновенно применяет силу выталкивания $F = \frac{\Delta x}{\Delta t^2} \cdot m$. | Для ящика массой 30 кг при пересечении 0.1 м сила составляет $>6000$ Н. Ящик выстреливает как ядро. |
| **Импульс броска (`ThrowImpulse.Plant`)** | Мод отслеживает скорость руки (`handVelocity`) и в течение 12 кадров после релиза принудительно перезаписывает `rb.velocity = _vel`. | Если предмет врезан в препятствие, принудительная перезапись скорости мешает солверу PhysX разрешить контакт, вызывая бесконечный рост реакции опоры. |

## 3. Практическое решение для разработчиков мода на физику

Чтобы сохранить физический бросок на открытом пространстве, но вернуть ванильное «втискивание» и убрать отлетание при перекрытии, мод должен проверять состояние пересечения в момент релиза:

```csharp
public static void HandleSafeRelease(ShipItem item, Rigidbody rb, Vector3 handVelocity)
{
    // 1. Проверяем глубину пересечения через ванильный чекер
    var checker = item.GetComponent<PickupableItemCollisionChecker>();
    bool isObstructed = false;
    
    if (checker != null && checker.collisions > 0)
    {
        // Читаем глубину проникновения (если >= 0.04 м — считаем перекрытием)
        if (!checker.allowObstructedDropping || item.big)
            isObstructed = true;
    }

    if (isObstructed)
    {
        // РЕЖИМ «ВТИСКИВАНИЯ» (Vanilla Reshuffle Mode):
        // 1. Не применяем ThrowImpulse (бросок отменяется при перекрытии)
        // 2. Временно оставляем twin-коллайдер в режиме isTrigger на 10 кадров
        rb.velocity = Vector3.zero;
        rb.angularVelocity = Vector3.zero;
        item.StartCoroutine(SoftResolveCoroutine(rb, item));
    }
    else
    {
        // Свободное пространство — запускаем честный импульс броска
        ThrowImpulse.Plant(rb, handVelocity);
    }
}
```

### 3.1. Чек-лист для устранения бага «shoot away»
1. **Не применяйте `ThrowImpulse` при активном красном контуре:** если предмет находится в состоянии пересечения (`collisions > 0` и `!allowObstructedDropping`), нажатие кнопки сброса/броска должно сбрасывать предмет без добавления скорости руки.
2. **Амортизация твердого коллайдера (`SoftResolve`):** после сброса перекрытого предмета переключайте `col.isTrigger = false` не мгновенно, а с задержкой в `0.15–0.25 с` (8–12 тактов `FixedUpdate`), чтобы геометрическая деколлизия успела вытолкнуть предмет без PhysX-взрыва.
3. **Ограничение максимальной скорости отскока:** установите на `Rigidbody` временный лимит скорости `rb.maxLinearVelocity = 2.5f` на первые 15 кадров после освобождения предмета из рук.
