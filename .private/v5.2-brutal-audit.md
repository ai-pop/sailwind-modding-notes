## 2. ROOT CAUSE: ForceMode.Acceleration EVERYWHERE

HoldDriver (only place we can SEE AddForce):
```csharp
_rb.AddForce(accel, ForceMode.Acceleration);
_rb.AddTorque(torque, ForceMode.Acceleration);
```

Config confession:
> "4.7-5.1 force model used pure accelerations → mass affected ONLY draft"

**ForceMode.Acceleration** = Unity divides force by mass automatically.
Item of 0.8kg and 50kg get IDENTICAL acceleration from same force call.
Mass affects ONLY Archimedes draft (_densityRatio). Nothing else.

### HoldDriver spring
```csharp
float mass = Mathf.Max(_rb.mass, 0.5f);
float lag = Mathf.Clamp(22f / mass, 0.4f, 1.6f);
Vector3 accel = (wantedVel - _rb.velocity) * (11f * lag);
_rb.AddForce(accel, ForceMode.Acceleration);
```
- `lag` curve gives ILLUSION of mass (heavy items lag more)
- But actual force is mass-independent
- This is a RESPONSE CURVE, not physics

### BlobPass (reconstructed from DLL strings)
```
buoyancyForce = submergedVolume * WaterDensity * g  ← correct Archimedes (N)
cappedForce = min(buoyancyForce, LiftCapG * mass * g)
AddForceAtPosition(Vector3.up * cappedForce, blobPos, Acceleration)
```
Archimedes calculated correctly in Newtons. But `ForceMode.Acceleration` divides by mass.
Result for big crate: `0.8*1000*9.81/50 = 157 m/s²` → capped at 2.2g ≈ 21.6 m/s².
Result for small cheese: `0.01*1000*9.81/0.8 = 122 m/s²` → capped at same 21.6 m/s².

**LiftCapG makes ALL items behave identically.** Mass is irrelevant.

## 3. SPECIFIC PROBLEMS

### Problem #1: ForceMode.Acceleration everywhere
Locations: HoldDriver, BlobPass, PivotPass, SharedForces.
Fix: `ForceMode.Force` everywhere. Unity then divides F by m automatically → heavy items accelerate slower. This IS physics.

### Problem #2: HoldDriver spring is not physics
Same ForceMode.Acceleration issue. Fix: ForceMode.Force + scale forces by mass.

### Problem #3: _densityRatio way too low
```
WaterDensity = 1000 kg/m³
boundsVolume of typical crate ≈ 0.5-1.0 m³
NeutralBuoyancyMass = 500-1000 kg
_densityRatio = 14-50 / 500-1000 = 0.014-0.10
```
Crate is 1-10% submerged — essentially ON TOP of water.
Real wooden crate with cargo: 40-80% submerged.

Fix: `waterDisplacedVolume = meshVolume * FillFactor` not `boundsVolume`.
FillFactor estimated from geometry or set in ItemSpec.

### Problem #4: MassFeelStrength doesn't fix root cause
Even at MassFeelStrength=1.0, if ForceMode.Acceleration is used, mass is divided BEFORE application. MassFeelStrength can only scale output, not restore true F=ma.

### Problem #5: Config overload — 30+ parameters
LiftCapG + WetUpCap + Freeboard + HeaveCoupling + DynamicsBoost + WaveTiltFactor all fight each other. Classic sign of tuning, not deriving from physics.

| # | Action | Location | Effect |
